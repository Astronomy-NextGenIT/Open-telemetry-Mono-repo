# Jenkins CI/CD Pipeline Documentation for Ad Service Deployment

## 1. Purpose

This document describes the complete CI/CD pipeline implementation for the Ad Service component of the OpenTelemetry Demo application.

The pipeline automates the following activities:

1. Fetch source code from Git repository.
2. Build a Docker image for Ad Service.
3. Authenticate with Amazon Elastic Container Registry (ECR).
4. Push the Docker image to ECR.
5. Update Kubernetes deployment manifests with the new image.
6. Deploy the updated application to Kubernetes.
7. Verify successful rollout.
8. Perform post-build cleanup.

---

# 2. Architecture Overview

The deployment workflow follows the sequence below:

Developer Code Commit
↓
Git Repository
↓
Jenkins Pipeline
↓
Docker Image Build
↓
Amazon ECR
↓
Kubernetes Deployment Update
↓
Application Running on Kubernetes Cluster

---

# 3. Prerequisites

Before creating the pipeline, the following components must be configured.

## 3.1 Jenkins Server

Jenkins server must be installed and operational.

Required plugins:

* Pipeline Plugin
* Git Plugin
* Credentials Plugin
* Docker Pipeline Plugin
* Kubernetes CLI Plugin (optional)

---

## 3.2 Docker Installation

Docker must be installed on the Jenkins server because the pipeline builds and pushes container images.

Verify installation:

```bash
docker --version
```

Required permissions:

* Jenkins user must belong to docker group.
* Jenkins should be able to execute Docker commands without sudo.

---

## 3.3 AWS CLI Installation

AWS CLI is required for ECR authentication.

Verify installation:

```bash
aws --version
```

---

## 3.4 AWS IAM Permissions

An IAM user or role must be configured with permissions for:

* Amazon ECR login
* Image push
* Image upload
* Repository access

Example permissions:

* ecr:GetAuthorizationToken
* ecr:BatchCheckLayerAvailability
* ecr:PutImage
* ecr:UploadLayerPart
* ecr:CompleteLayerUpload

AWS credentials must be configured on the Jenkins server.

---

## 3.5 Amazon ECR Repository

An ECR repository must exist before pipeline execution.

Example:

```
open-telemetry-registry
```

Purpose:

* Stores versioned Docker images generated by Jenkins.

---

## 3.6 Kubernetes Cluster

A running Kubernetes cluster must be available.

The cluster may be:

* Self-managed Kubernetes
* kubeadm cluster
* Amazon EKS
* Any CNCF-compliant cluster

---

## 3.7 kubectl Configuration

kubectl must be installed on Jenkins.

Verify installation:

```bash
kubectl version --client
```

Jenkins server must contain a valid kubeconfig file that allows access to the target cluster.

Verify connectivity:

```bash
kubectl get nodes
```

Expected result:

* All nodes should be in Ready state.

# 4. Repository Structure

The pipeline expects the following structure inside the Git repository.

```text
src/
 └── ad/
      ├── Dockerfile
      └── kubernetes/
           └── ad/
                ├── deploy.yaml
                └── svc.yaml
```

Files:

Dockerfile

* Builds Ad Service image.

deploy.yaml

* Kubernetes deployment definition.

svc.yaml

* Kubernetes service definition.

# Complete pipeline


pipeline {
    agent any

    environment {

        AWS_REGION = "ap-south-1"
        AWS_ACCOUNT_ID = "<Add your AWS_ACCOUNT_ID>"

        ECR_REPO = "open-telemetry-registry"

        IMAGE_NAME = "ad"

        IMAGE_TAG = "${BUILD_NUMBER}"

        ECR_URI = "${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPO}"

        K8S_DEPLOYMENT = "opentelemetry-demo-adservice"
        NAMESPACE = "default"
    }

    stages {

        stage('Checkout') {
            steps {
                git branch: 'main',
                url: 'https://github.com/<organization>/<repository>.git'
            }
        }

        stage('Verify Tools') {
            steps {
                sh '''
                aws --version
                kubectl version --client
                docker --version
                '''
            }
        }

        stage('ECR Login') {
            steps {
                sh '''
                aws ecr get-login-password \
                --region ${AWS_REGION} | \
                docker login \
                --username AWS \
                --password-stdin \
                ${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com
                '''
            }
        }

        stage('Build Docker Image') {
            steps {
                sh '''
                docker build \
                --build-arg OTEL_JAVA_AGENT_VERSION=2.16.0 \
                -t ${IMAGE_NAME}:${IMAGE_TAG} \
                -f src/ad/Dockerfile .
                '''
            }
        }

        stage('Tag Image') {
            steps {
                sh '''
                docker tag \
                ${IMAGE_NAME}:${IMAGE_TAG} \
                ${ECR_URI}:${IMAGE_TAG}
                '''
            }
        }

        stage('Push Image To ECR') {
            steps {
                sh '''
                docker push ${ECR_URI}:${IMAGE_TAG}
                '''
            }
        }

        stage('Update Manifest') {
            steps {
                sh '''
                sed -i "s|image:.*|image: ${ECR_URI}:${IMAGE_TAG}|g" \
                src/ad/kubernetes/ad/deploy.yaml

                cat src/ad/kubernetes/ad/deploy.yaml | grep image
                '''
            }
        }

        stage('Deploy To Kubernetes') {
            steps {
                sh '''
                kubectl apply -f src/ad/kubernetes/ad/deploy.yaml
                kubectl apply -f src/ad/kubernetes/ad/svc.yaml
                '''
            }
        }

        stage('Rollout Status') {
            steps {
                sh '''
                kubectl rollout status deployment/${K8S_DEPLOYMENT} -n ${NAMESPACE}
                '''
            }
        }
    }

    post {

        success {
            echo 'Ad Service Deployment Successful'
        }

        failure {
            echo 'Pipeline Failed'
        }

        always {
            sh '''
            docker image prune -f || true
            '''
        }
    }
}

# 5. Pipeline Implementation

The Jenkins pipeline consists of multiple stages that execute sequentially to build, package, publish, and deploy the Ad Service application.

---

## Stage 1: Checkout Source Code

### Objective

The purpose of this stage is to retrieve the latest source code from the Git repository so that Jenkins can build the most recent version of the application.

### Jenkins Configuration

The pipeline connects to the configured Git repository and checks out the **main** branch.

### Pipeline Code

```groovy
stage('Checkout') {
    steps {
        git branch: 'main',
        url: 'https://<git-repository-url>'
    }
}
```

### Execution Flow

1. Jenkins establishes a connection with the Git repository.
2. Authentication is performed if required.
3. The main branch is cloned into the Jenkins workspace.
4. All source files become available for subsequent stages.

### Expected Output

```text
Checking out Revision xxxx
Branch main
Finished cloning repository
```

### Importance

* Ensures the latest code is used for deployment.
* Provides a clean source code base for the build process.
* Eliminates manual source code transfers.

---

## Stage 2: Verify Tools

### Objective

Before beginning the build and deployment process, Jenkins verifies that all required tools are installed and accessible.

### Tools Verified

| Tool    | Purpose               |
| ------- | --------------------- |
| AWS CLI | ECR Authentication    |
| Docker  | Image Build and Push  |
| kubectl | Kubernetes Deployment |

### Pipeline Code

```groovy
stage('Verify Tools') {
    steps {
        sh '''
        aws --version
        kubectl version --client
        docker --version
        '''
    }
}
```

### Execution Flow

1. Jenkins executes version-check commands.
2. System verifies the availability of:

   * AWS CLI
   * kubectl
   * Docker
3. If any command fails, the pipeline stops immediately.

### Expected Output

```text
aws-cli/2.x.x
Client Version: v1.30.x
Docker version 27.x.x
```

### Importance

* Prevents deployment failures caused by missing tools.
* Validates Jenkins server configuration before continuing.

---

## Stage 3: Amazon ECR Authentication

### Objective

Authenticate the Jenkins server with Amazon Elastic Container Registry (ECR) so Docker images can be pushed securely.

### Pipeline Code

```groovy
stage('ECR Login') {
    steps {
        sh '''
        aws ecr get-login-password \
        --region ${AWS_REGION} | \
        docker login \
        --username AWS \
        --password-stdin \
        <ECR-ENDPOINT>
        '''
    }
}
```

### Execution Flow

1. Jenkins requests an authentication token from AWS.
2. AWS returns a temporary ECR login password.
3. Docker uses the password to authenticate with ECR.
4. Secure communication is established.

### Expected Output

```text
Login Succeeded
```

### Importance

* Enables image push operations.
* Provides secure access to the ECR repository.
* Avoids hardcoding passwords in Jenkins.

---

## Stage 4: Build Docker Image

### Objective

Build a Docker image for the Ad Service application.

### Pipeline Code

```groovy
stage('Build Docker Image') {
    steps {
        sh '''
        docker build \
        --build-arg OTEL_JAVA_AGENT_VERSION=2.16.0 \
        -t ${IMAGE_NAME}:${IMAGE_TAG} \
        -f src/ad/Dockerfile .
        '''
    }
}
```

### Build Inputs

| Input          | Description                 |
| -------------- | --------------------------- |
| Dockerfile     | Ad Service Dockerfile       |
| Source Code    | Application Source          |
| Build Argument | OpenTelemetry Agent Version |

### Execution Flow

1. Docker reads the Dockerfile.
2. Required base images are downloaded.
3. Application artifacts are copied.
4. OpenTelemetry Java Agent version is injected.
5. Image layers are created.
6. Final image is generated.

### Example Image

```text
ad:25
```

### Expected Output

```text
Successfully built abc123
Successfully tagged ad:25
```

### Importance

* Packages application into a portable container.
* Ensures consistency across environments.
* Supports Kubernetes deployment.

---

## Stage 5: Tag Docker Image

### Objective

Prepare the locally built image for storage in Amazon ECR.

### Pipeline Code

```groovy
stage('Tag Image') {
    steps {
        sh '''
        docker tag \
        ${IMAGE_NAME}:${IMAGE_TAG} \
        ${ECR_URI}:${IMAGE_TAG}
        '''
    }
}
```

### Execution Flow

1. Jenkins identifies the local image.
2. A new ECR-compliant tag is created.
3. The image now contains:

   * Local tag
   * ECR tag

### Example

Before:

```text
ad:25
```

After:

```text
<ecr-repository>:25
```

### Importance

* Required before image upload.
* Associates image with the correct ECR repository.

---

## Stage 6: Push Image to Amazon ECR

### Objective

Upload the Docker image into Amazon ECR.

### Pipeline Code

```groovy
stage('Push Image To ECR') {
    steps {
        sh '''
        docker push ${ECR_URI}:${IMAGE_TAG}
        '''
    }
}
```

### Execution Flow

1. Docker connects to ECR.
2. Image layers are uploaded.
3. Image manifest is created.
4. Image becomes available in ECR.

### Expected Output

```text
Layer already exists
Pushed
latest digest: sha256:xxxx
```

### Importance

* Stores application images centrally.
* Makes images accessible to Kubernetes nodes.

---

## Stage 7: Update Kubernetes Manifest

### Objective

Update the deployment manifest with the newly created image tag.

### Pipeline Code

```groovy
stage('Update Manifest') {
    steps {
        sh '''
        sed -i "s|image:.*|image: ${ECR_URI}:${IMAGE_TAG}|g" \
        src/ad/kubernetes/ad/deploy.yaml
        '''
    }
}
```

### Execution Flow

1. Jenkins opens deploy.yaml.
2. Existing image reference is identified.
3. New ECR image tag is inserted.
4. Manifest file is updated.

### Example

Before:

```yaml
image: repository/ad:20
```

After:

```yaml
image: repository/ad:25
```

### Importance

* Ensures Kubernetes deploys the latest image.
* Eliminates manual YAML updates.

---

## Stage 8: Deploy to Kubernetes

### Objective

Deploy the updated application into the Kubernetes cluster.

### Pipeline Code

```groovy
stage('Deploy To Kubernetes') {
    steps {
        sh '''
        kubectl apply -f deploy.yaml
        kubectl apply -f svc.yaml
        '''
    }
}
```

### Execution Flow

1. Deployment manifest is applied.
2. Service manifest is applied.
3. Kubernetes detects image changes.
4. Rolling update process starts.

### Resources Created/Updated

| Resource   | Purpose                |
| ---------- | ---------------------- |
| Deployment | Pod Management         |
| Service    | Internal Communication |

### Importance

* Automates Kubernetes deployment.
* Ensures zero or minimal downtime deployment.

---

## Stage 9: Rollout Status Verification

### Objective

Verify that the deployment has completed successfully.

### Pipeline Code

```groovy
stage('Rollout Status') {
    steps {
        sh '''
        kubectl rollout status deployment/${K8S_DEPLOYMENT}
        '''
    }
}
```

### Execution Flow

1. Jenkins monitors deployment status.
2. Kubernetes creates new pods.
3. Health checks execute.
4. Old pods terminate.
5. Deployment completes.

### Expected Output

```text
deployment successfully rolled out
```
